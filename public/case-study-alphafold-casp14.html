Research Quest · Cognition Map + grill-me-with-docs

先读资料，再问一个真正重要的问题

Research Quest 的核心不是把科研包装成网页游戏，而是让 AI 先读懂项目资料，再用 Known–Unknown 四象限找到最关键的认知空缺。用户既可以回答问题，也可以随时追问或主动补充新的上下文和任务线索。

认知地图决定问题 · 文档减少重复沟通 · Context 交给 Codex

为什么一句命令通常不够

真实需求

“帮我判断 AlphaFold2 能不能用于酶活性位点分析。”

这句话说明了研究对象，却没有说明最先要支持什么判断、手里有什么资料、结果最多能说明什么，以及做到什么才算完成。直接交给 Codex，它只能一边执行一边猜。

Research Quest 不会马上给出一份很长的方案。它先读取文档和已有讨论，把材料已经回答的内容放进认知地图，只追问材料无法回答、又最影响结果的问题。

两个核心逻辑

Known–Unknown 四象限

四象限告诉 AI：用户已经掌握什么、明确不知道什么、可能会但还没表达什么，以及还有哪些隐藏风险没有被看到。

grill-me-with-docs

AI 先读文档，不重复问材料里已有的答案；默认每轮只问一个关键问题，并尽量沿用用户已经使用的术语。

认知地图固定包含四部分

Known Knowns

已知的已知

用户已经明确并能够使用的内容，例如研究对象和已经确认的目标。

Unknown Knowns

未知的已知

用户可能已经有经验或偏好，但还没有主动说出来。

Known Unknowns

已知的未知

用户知道还缺答案的问题，例如这项结果最多能说明什么。

Unknown Unknowns

未知的未知

需要通过反例、失败或真实执行才会出现的隐藏问题。

聊天界面不反复展示横轴和纵轴文字，但四个位置和含义固定。问题、解释、进度和 Goal 变化都由这张地图产生。

5 轮聊天怎样把需求说清楚

  1. 先说清楚要解决什么已有资料只说明研究对象，因此先问：你最想让这项工作帮助你判断什么？
  2. 看看手里有什么资料目标已经明确，再确认是否有 AlphaFold DB 预测、实验 PDB 和催化残基注释。
  3. 确认结果最多能说明什么资料够不等于结论可以无限扩大，因此先确定只做局部结构初筛，还是还要加入对接。
  4. 约定做到什么才算完成目标、资料和结果范围都明确后，只需要补一个可检查的完成标准。
  5. 停止提问，交给 Codex关键 Known Unknowns 已经有答案，剩余问题必须通过执行解决，因此整理 Context 和 Goal。

用户也可以主动补充上下文和任务线索

倒数第二个选项：我想补充上下文或任务线索

用户可以主动添加资料、约束、偏好、截止时间、目标修正、实验结果、文件说明或纠错。AI 不要求用户等到被问到才提供信息。

Research Quest · 上下文与任务线索

类型：资料与待核对事实。状态：Candidate。

已记录存在一份注释表，但读取和核对前不能把它当成可直接使用的资料。当前 Goal 将加入字段与编号审查步骤。

主进度暂停；认知地图新增资料 Candidate 和编号对齐风险。

用户对自己目标、偏好、约束和截止时间的明确陈述可以记为 Confirmed；文件内容、数据、实验结果和外部事实在核验前只能记为 Candidate。与已有 Context 冲突时，AI 必须展示冲突，不能静默覆盖。

用户主动补充
→ 线索分类
→ Candidate / Confirmed
→ 去重与冲突检查
→ 更新四象限与 Context
→ Goal 保持、修改或回滚
→ 缩小、跳过或重写当前 grill-me 问题

两种中断的区别

我还有问题

用户希望 AI 提供答案。系统生成“关卡线索”，先回答，再更新认知地图。

我想补充线索

用户希望把新信息加入任务。系统生成“上下文与任务线索”，先分类和核验，再更新 Goal。

“为什么这一步最值得问”不是固定话术

生成规则

AI 必须同时说明：文档已经告诉了我们什么、当前四象限最大的空缺是什么，以及这个空缺会怎样改变最终 Goal。

Context 保存的不只是最终结论

research-quest-context.md

完整 Context 保存已读资料、主问题、用户选择、额外问题与答案、主动任务线索、四象限状态、Candidate / Confirmed / Verified 证据、Goal 版本变化、开放未知和关闭条件。

有文件或知识库写入能力时，AI 应明确写入路径；只有浏览器内存或会话状态时，必须如实说明“导出后保存为某文件”，不能假装已经写入磁盘。

最终交给 Codex 的内容

Frozen Context
+ 真实目标与非目标
+ 已读材料和用户偏好
+ Known–Unknown 四象限
+ 关卡线索与问答记录
+ 用户主动追加的任务线索
+ 当前目标变化历史
+ 输入、步骤、指标和完成标准
+ Agent 分工、测试和审查
+ 3–5 轮失败后的根因分析
→ Codex 执行

案例的事实边界

AlphaFold2 在 CASP14 中展示了重要的结构预测能力，AlphaFold DB 提供公开预测结构。但本案例只是演示如何设计一个公开试点，尚未提供“10 个目标已完成”的科研结果，也不把 pLDDT 或结构相似性直接解释为催化活性或底物结合正确。

公开背景：AlphaFold2 Nature 论文 · AlphaFold DB · PDBe
