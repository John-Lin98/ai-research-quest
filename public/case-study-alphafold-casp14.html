Research Quest · Cognition Map + grill-me-with-docs

把科研任务聊清楚，再交给 Codex 执行

Research Quest 不是把科研包装成一款独立游戏，而是用游戏式、回合式交互帮助用户持续表达目标、偏好、疑问和限制，让 AI 获得足够准确的 Context。随后，AI 再把完整 Context 和 Goal 交给 Codex 或 Agent 执行。

游戏式需求对齐 · 认知地图驱动提问 · Context + Goal 交给 Codex

为什么一句命令通常不够

真实需求

“帮我判断 AlphaFold2 能不能用于酶活性位点分析。”

这句话说明了研究对象，却没有说明最先要支持什么判断、手里有什么资料、结果最多能说明什么，以及做到什么才算完成。直接交给 Codex，它只能一边执行一边猜。

Research Quest 不会马上输出一份很长的方案。它先读取文档和已有讨论，把材料已经回答的内容放进认知地图，只追问材料无法回答、又最影响最终结果的问题。

游戏式对齐为什么能得到更完整的 Context

降低表达负担

一次只处理一个最高价值问题，用户不必先组织一份完美需求文档，也不会被十几个问题同时压住。

让变化看得见

每轮都展示四象限、进度和当前目标变化，用户能看见自己的回答怎样改变任务，更容易及时补充或纠错。

鼓励持续参与

关卡、进度与正反馈让需求沟通不再只是枯燥命令。用户更愿意表达偏好、失败经验和隐藏限制，AI 因此获得更充分的 Context。

核心收益

游戏化不是表面装饰。它服务于需求对齐：让用户更轻松地持续提供信息，让 AI 更准确地理解任务，最终为 Codex 准备一份更完整、可追溯、可执行的 Context。

为什么要克制提问和回答

降低用户获取信息的难度

AI 每轮只问一个最高价值问题，并只回答当前真正需要理解的部分。用户不必一次面对十几个问题，也不用从长篇回答里自己寻找最关键的结论。

降低 AI 的上下文和推理负担

更短、更聚焦的回合可以减少无关 Context 持续累积，避免尚未确认的假设进入后续推理与 Goal，让 AI 更容易持续对齐用户真正想完成的任务。

克制不等于省略必要信息。需要深入时，用户可以继续追问；材料、风险或冲突发生变化时，AI 也会依据认知地图补充解释。目标是每一轮只解决当前最有价值的不确定性。

两个核心逻辑

Known–Unknown 四象限

四象限告诉 AI：用户已经掌握什么、明确不知道什么、可能会但还没表达什么，以及还有哪些隐藏风险没有被看到。

grill-me-with-docs

AI 先读文档，不重复问材料里已有的答案；默认每轮只问一个关键问题，并尽量沿用用户已经使用的术语。

认知地图固定包含四部分

Known Knowns（已知的已知）

用户已经明确并能够使用的内容，例如研究对象和已经确认的目标。

Unknown Knowns（未知的已知）

用户可能已经有经验或偏好，但还没有主动说出来。

Known Unknowns（已知的未知）

用户知道还缺答案的问题，例如这项结果最多能说明什么。

Unknown Unknowns（未知的未知）

需要通过反例、失败或真实执行才会出现的隐藏问题。

认知地图怎样调整下一轮

上一轮 Verified Known Knowns 较少
→ 下一轮自动减少术语
→ 增加基础解释与具体对比
→ 用户掌握后再进入方案取舍

Known Unknowns 已基本关闭
→ 停止重复问基础问题
→ 转向完成标准、风险或执行验证

发现新的 Unknown Unknown
→ 暂停原路线
→ 插入隐藏风险关
→ 更新 Context 与 Goal 后再继续

因此，认知地图不是一个展示面板，而是下一轮问题生成器。“为什么这一步最值得问”必须同时说明：文档已经告诉了什么、四象限最大的空缺是什么，以及这个空缺会怎样改变最终 Goal。

Research Quest 怎样帮助用户澄清科研需求

Research Quest 不预设固定轮数。任务简单时可能只需要两三轮；材料较多、冲突较多或目标尚不清楚时，轮数会随认知地图动态变化。核心不是“完成五关”，而是把影响执行的关键未知逐步关闭。

  1. 先读材料，整理已经知道的内容AI 读取文档、历史讨论和当前 Context，不再重复询问材料已经回答的问题。
  2. 建立认知地图，找到最大的空缺把明确事实、未表达经验、已知问题和隐藏风险放入固定四象限。
  3. 一次只问一个最高价值问题问题必须会改变目标、资料、结果范围、完成标准或执行方式，并尽量沿用用户已经使用的词。
  4. 接收回答、追问和主动任务线索用户可以选择答案、要求解释，也可以补充资料、约束、偏好、截止时间、结果或纠错。
  5. 更新四象限、Context 与当前 Goal新信息先分类和核验，再决定缩小原问题、跳过已解决问题、处理冲突或插入隐藏风险关。
  6. 满足交接条件后停止提问当影响执行的核心 Known Unknowns 已有答案或关闭条件，就生成完整 Context 与 Goal，交给 Codex 或 Agent 执行。

Research Quest 如何提供正反馈

每轮都让用户知道“刚才发生了什么”

  • 目标进度条与百分比
    告诉用户任务离可执行状态还有多远。
  • 认知分变化
    只奖励被确认或正确应用的知识，不把随意回答当成掌握。
  • 预计剩余时间
    减少“还要聊多久”的不确定感，避免无限访谈。
  • 当前目标变化 (Goal vN)
    直接显示本轮选择如何改变最终任务、步骤或验收。

每次用户作出选择、提出问题或补充线索后，界面都会立即更新这四类反馈。用户由此看到“刚才输入了什么、它改变了什么、还剩多少、下一步为什么这样问”，并能及时纠正 AI 对任务的理解。

用户可以随时暂停闯关提问

最后一个选项：暂不闯关，我还有一些问题

暂停不会推进关卡、不会扣分，也不会把原问题标记为已回答。

两种中断的区别

我还有问题

用户希望 AI 提供答案。系统生成“关卡线索”，先回答，再更新认知地图。

我想补充线索

用户希望把新信息加入任务。系统生成“上下文与任务线索”，先分类和核验，再更新 Goal。

用你喜欢的方式制作自己的游戏 Skill

Research Quest 提供的是一套可复用的交互方法，而不是固定的美术或剧情模板。你可以保留“认知地图 + grill-me-with-docs + Context / Goal 交接”的核心，再换成自己喜欢的游戏方式。

选择游戏风格

可以做成 RPG、侦探推理、卡牌构筑、经营养成、冒险探索，或任何适合目标用户的互动形式。

让模型参与创作

可以让 Sol、Fable、Kimi 等你常用的模型帮助设计角色、剧情、关卡、奖励、反馈和交互文案，发挥它们的游戏化创作能力。

根据认知地图持续优化

用户的选择、追问、卡点和主动线索会更新认知地图；AI 再据此调整难度、叙事和下一轮问题，让 Skill 的交互逐步贴近用户。

可复用思路

先确定你希望游戏帮助用户完成什么，再设计认知地图、每轮问题、正反馈和最终交付。游戏风格可以自由变化，但每个关卡都应帮助 AI 获得更准确的 Context，而不是只增加装饰。

Context 保存的不只是最终结论

research-quest-context.md

完整 Context 保存已读资料、主问题、用户选择、额外问题与答案、主动任务线索、四象限状态、Candidate / Confirmed / Verified 证据、Goal 版本变化、开放未知和关闭条件。

有文件或知识库写入能力时，AI 应明确写入路径；只有浏览器内存或会话状态时，必须如实说明“导出后保存为某文件”，不能假装已经写入磁盘。

最终同时交给 Codex：Context 与 Goal

Context 负责告诉 Codex“用户真正想做什么、讨论过什么、哪些信息可信”；Goal 负责告诉 Codex“接下来具体怎样执行、怎样验收和何时停止”。两者缺一不可。
