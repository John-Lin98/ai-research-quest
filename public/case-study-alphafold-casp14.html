Research Quest · Cognition Map + grill-me-with-docs

把科研任务聊清楚，再交给 Codex 执行

Research Quest 不是把科研包装成一款独立游戏，而是用游戏式、回合式交互帮助用户持续表达目标、偏好、疑问和限制，让 AI 获得足够准确的 Context。随后，AI 再把完整 Context 和 Goal 交给 Codex 或 Agent 执行。

游戏式需求对齐 · 认知地图驱动提问 · Context + Goal 交给 Codex

为什么一句命令通常不够

真实需求

“帮我判断 AlphaFold2 能不能用于酶活性位点分析。”

这句话说明了研究对象，却没有说明最先要支持什么判断、手里有什么资料、结果最多能说明什么，以及做到什么才算完成。直接交给 Codex，它只能一边执行一边猜。

Research Quest 不会马上输出一份很长的方案。它先读取文档和已有讨论，把材料已经回答的内容放进认知地图，只追问材料无法回答、又最影响最终结果的问题。

游戏式对齐为什么能得到更完整的 Context

降低表达负担

一次只处理一个最高价值问题，用户不必先组织一份完美需求文档，也不会被十几个问题同时压住。

让变化看得见

每轮都展示四象限、进度和当前目标变化，用户能看见自己的回答怎样改变任务，更容易及时补充或纠错。

鼓励持续参与

关卡、进度与正反馈让需求沟通不再只是枯燥命令。用户更愿意表达偏好、失败经验和隐藏限制，AI 因此获得更充分的 Context。

核心收益

游戏化不是表面装饰。它服务于需求对齐：让用户更轻松地持续提供信息，让 AI 更准确地理解任务，最终为 Codex 准备一份更完整、可追溯、可执行的 Context。

两个核心逻辑

Known–Unknown 四象限

四象限告诉 AI：用户已经掌握什么、明确不知道什么、可能会但还没表达什么，以及还有哪些隐藏风险没有被看到。

grill-me-with-docs

AI 先读文档，不重复问材料里已有的答案；默认每轮只问一个关键问题，并尽量沿用用户已经使用的术语。

认知地图固定包含四部分

Known Knowns

已知的已知

用户已经明确并能够使用的内容，例如研究对象和已经确认的目标。

Unknown Knowns

未知的已知

用户可能已经有经验或偏好，但还没有主动说出来。

Known Unknowns

已知的未知

用户知道还缺答案的问题，例如这项结果最多能说明什么。

Unknown Unknowns

未知的未知

需要通过反例、失败或真实执行才会出现的隐藏问题。

聊天界面不反复展示横轴和纵轴文字，但四个位置和含义固定。问题、解释、进度和 Goal 变化都由这张地图产生。

认知地图怎样调整下一轮

上一轮 Verified Known Knowns 较少
→ 下一轮自动减少术语
→ 增加基础解释与具体对比
→ 用户掌握后再进入方案取舍

Known Unknowns 已基本关闭
→ 停止重复问基础问题
→ 转向完成标准、风险或执行验证

发现新的 Unknown Unknown
→ 暂停原路线
→ 插入隐藏风险关
→ 更新 Context 与 Goal 后再继续

因此，认知地图不是一个展示面板，而是下一轮问题生成器。“为什么这一步最值得问”必须同时说明：文档已经告诉了什么、四象限最大的空缺是什么，以及这个空缺会怎样改变最终 Goal。

5 轮聊天怎样把需求说清楚

  1. 先说清楚要解决什么已有资料只说明研究对象，因此先问：你最想让这项工作帮助你判断什么？
  2. 看看手里有什么资料目标已经明确，再确认是否有 AlphaFold DB 预测、实验 PDB 和催化残基注释。
  3. 确认结果最多能说明什么资料够不等于结论可以无限扩大，因此先确定只做局部结构初筛，还是还要加入对接。
  4. 约定做到什么才算完成目标、资料和结果范围都明确后，只需要补一个可检查的完成标准。
  5. 停止提问，交给 Codex关键 Known Unknowns 已有答案，剩余问题必须通过执行解决，因此整理 Context 和 Goal。

正反馈为什么重要

每轮都让用户知道“刚才发生了什么”

  • 目标进度条与百分比
    告诉用户任务离可执行状态还有多远。
  • 认知分变化
    只奖励被确认或正确应用的知识，不把随意回答当成掌握。
  • 预计剩余时间
    减少“还要聊多久”的不确定感，避免无限访谈。
  • 当前目标变化 (Goal vN)
    直接显示本轮选择如何改变最终任务、步骤或验收。

这些反馈不是为了制造虚拟分数，而是帮助用户理解自己的决定、保持参与感，并及时发现 AI 是否误解了任务。

用户也可以主动补充上下文和任务线索

倒数第二个选项：我想补充上下文或任务线索

用户可以主动添加资料、约束、偏好、截止时间、目标修正、实验结果、文件说明或纠错。AI 不要求用户等到被问到才提供信息。

Research Quest · 上下文与任务线索

类型：资料与待核对事实。状态：Candidate。

已记录存在一份注释表，但读取和核对前不能把它当成可直接使用的资料。当前 Goal 将加入字段与编号审查步骤。

主进度暂停；认知地图新增资料 Candidate 和编号对齐风险。

用户对自己目标、偏好、约束和截止时间的明确陈述可以记为 Confirmed；文件内容、数据、实验结果和外部事实在核验前只能记为 Candidate。与已有 Context 冲突时，AI 必须展示冲突，不能静默覆盖。

用户主动补充
→ 线索分类
→ Candidate / Confirmed
→ 去重与冲突检查
→ 更新四象限与 Context
→ Goal 保持、修改或回滚
→ 缩小、跳过或重写当前 grill-me 问题

两种中断的区别

我还有问题

用户希望 AI 提供答案。系统生成“关卡线索”，先回答，再更新认知地图。

我想补充线索

用户希望把新信息加入任务。系统生成“上下文与任务线索”，先分类和核验，再更新 Goal。

点击选项怎样成为真实输入

支持按钮的宿主

用户点击后，选项直接生成带头像的用户气泡，并写入 Context、认知地图和 Goal vN。

不支持按钮的宿主

每个选项提供完整可复制文本；用户复制并发送，也可以直接输入自己的答案、问题或任务线索。

Context 保存的不只是最终结论

research-quest-context.md

完整 Context 保存已读资料、主问题、用户选择、额外问题与答案、主动任务线索、四象限状态、Candidate / Confirmed / Verified 证据、Goal 版本变化、开放未知和关闭条件。

有文件或知识库写入能力时，AI 应明确写入路径；只有浏览器内存或会话状态时，必须如实说明“导出后保存为某文件”，不能假装已经写入磁盘。

最终交给 Codex 的内容

Frozen Context
+ 真实目标与非目标
+ 已读材料和用户偏好
+ Known–Unknown 四象限
+ 关卡线索与问答记录
+ 用户主动追加的任务线索
+ 当前目标变化历史
+ 输入、步骤、指标和完成标准
+ Agent 分工、测试和审查
+ 3–5 轮失败后的根因分析
→ Codex 执行

案例的事实边界

AlphaFold2 在 CASP14 中展示了重要的结构预测能力，AlphaFold DB 提供公开预测结构。但本案例只是演示如何设计一个公开试点，尚未提供“10 个目标已完成”的科研结果，也不把 pLDDT 或结构相似性直接解释为催化活性或底物结合正确。
