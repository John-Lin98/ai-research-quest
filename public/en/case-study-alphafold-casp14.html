Research Quest · cognition map + grill-me-with-docs

Clarify the research task before asking Codex to execute it

Research Quest turns research alignment into a small-step, game-like conversation. The goal is not decorative gamification: it is to help users express the real objective, constraints, preferences, questions, and evidence limits while the AI builds a sufficiently accurate Context.

Gamified alignment · cognition-map-driven questions · Context + Goal handoff

Why one instruction is often not enough

Example request

“Help me decide whether AlphaFold2 can be used for enzyme active-site analysis.”

The request names the research object, but it does not state the first downstream decision, the material already available, how far the evidence may support a conclusion, or what counts as complete. If Codex starts immediately, it must guess while executing.

Research Quest reads documents and existing discussion first. It then asks only what the material cannot answer and what can materially change the final Goal.

Why game-like alignment can produce better Context

Lower expression burden

The user handles one high-value decision at a time instead of preparing a perfect specification up front.

Make change visible

Each turn shows how the map, progress, and current Goal changed, so misunderstandings can be corrected early.

Encourage continued participation

Turns, progress, and concrete feedback make it easier to reveal preferences, failure experience, and hidden constraints.

Core benefit

Gamification serves alignment. It helps the user keep supplying useful information and helps the AI prepare a more complete, traceable, and executable Context for Codex.

Why the questions and answers stay restrained

Reduce the user's information burden

One high-value question and one focused answer are easier to understand than a questionnaire followed by a long general essay.

Reduce AI context and reasoning drift

Short, focused turns reduce irrelevant Context growth and make it harder for an unconfirmed assumption to contaminate later reasoning and Goal updates.

Restraint does not mean hiding necessary information. The user can ask follow-up questions at any time, and the AI expands only when the documents, cognition map, risk, or conflict requires it.

The two core mechanisms

Known–Unknown cognition map

Tracks what is explicit, what the user may already know but has not expressed, what remains an acknowledged question, and what hidden risks may emerge only through counterexamples or execution.

grill-me-with-docs

Reads supplied material before asking. It avoids repeated questions, reuses the user's terminology, and defaults to one question that can change the final plan.

The fixed four-quadrant map

Known Knowns

Knowledge the user has expressed, confirmed, or correctly applied.

Unknown Knowns

Experience, judgement, or preference the user may possess but has not yet articulated.

Known Unknowns

Questions the user already knows are unresolved and that can change the task.

Unknown Unknowns

Hidden issues that may require conflicts, failures, prototypes, or real execution to expose.

Known Knowns follow an evidence progression: Candidate → Confirmed → Verified. A summary or claim does not become Verified merely because the AI wrote it.

How the cognition map changes the next turn

Few Verified Known Knowns
→ reduce terminology and add concrete explanation
→ return to research trade-offs only after the foundation is understood

Known Unknowns are mostly closed
→ stop repeating foundational questions
→ move to completion rules, risk, or execution validation

A new Unknown Unknown appears
→ pause the original route
→ add a risk branch
→ update Context and Goal before continuing

The cognition map is therefore a question generator, not a display-only panel. “Why this is the highest-value question now” should explain what the documents already establish, which quadrant contains the largest gap, and how closing that gap changes the Goal.

How Research Quest clarifies a research need

The Skill does not require a fixed number of turns. A simple task may take two or three; a conflicting or under-specified task may need more. The stopping rule is not “complete five levels” but “close the conversational unknowns that block execution.”

  1. Read material firstExtract the facts, terminology, constraints, and preferences already present.
  2. Build the cognition mapSeparate explicit knowledge, unspoken experience, open questions, and hidden risks.
  3. Ask one high-value questionChoose the question most likely to change the objective, evidence, completion rule, or execution route.
  4. Accept three forms of user inputThe user can answer, ask the AI a question, or add Context and task clues proactively.
  5. Update Context and GoalClassify evidence, detect duplicates and conflicts, then shrink, skip, or rewrite the next question.
  6. Stop and hand offWhen more conversation no longer changes the executable plan, generate both Frozen Context and Codex Goal.

How the interface provides positive feedback

  • Goal progress and percentage
    Shows how close the task is to an executable state.
  • Cognition-score change
    Rewards confirmed or correctly applied understanding, not arbitrary answers.
  • Estimated remaining time
    Reduces uncertainty about how long alignment will continue.
  • Current Goal change (Goal vN)
    Shows exactly how the latest decision changed the plan.

Users can interrupt the main path

I have a question

The main question pauses. The AI answers from the documents first, saves the Q&A as a clue, updates the map, and replans the current question without advancing progress.

I want to add Context or a task clue

The user can add documents, constraints, preferences, deadlines, results, or corrections. The AI classifies the clue, checks evidence and conflicts, updates Context and Goal, and then resumes.

User statements about their own goals, preferences, constraints, deadlines, and deliverables may be Confirmed. File contents, experiment results, and external facts remain Candidate until read or verified. Conflicts must be displayed rather than silently overwritten.

Build your own game Skill

Research Quest provides a reusable interaction method rather than a fixed art style or story. Keep the cognition map, document-first questioning, evidence states, and Context / Goal handoff, then adapt the presentation to an RPG, detective story, card game, management simulation, exploration game, or another style that fits your users.

Models such as Sol, Fable, or Kimi can help draft characters, narratives, levels, rewards, and interaction copy. Their role here is creative assistance, not a claim that they have been benchmarked against one another.

The final handoff includes both Context and Goal

Context explains what the user actually wants, what was discussed, and which information is trustworthy. Goal specifies what Codex should do, how success is checked, and when to stop. Neither is sufficient alone.

How execution results return to Context

Boundary of the public case

The AlphaFold2 example demonstrates product logic and a public pilot design. It does not provide completed results for specific enzyme targets and does not treat pLDDT or structural similarity as proof of catalytic activity or substrate binding.
