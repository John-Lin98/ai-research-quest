# Research Quest

Research Quest 不是给聊天套一层游戏外观，而是一个**文档驱动的科研目标对齐 Skill**。

它的核心只有两部分：

1. **Known–Unknown 四象限认知地图**：判断用户已经知道什么、意识到什么，以及还遗漏什么；
2. **grill-me-with-docs 小步提问**：先读文档与已有 Context，只问材料无法回答、且最影响最终任务的一个问题。

```text
真实科研需求 + 文档 + 历史讨论
→ 先读材料，不重复询问
→ 建立 Known–Unknown 四象限
→ 每轮默认只问一个关键问题
→ 用户可暂停主线并提问
→ 生成关卡线索、更新地图、重写当前问题
→ 保存选择、问答与 Goal vN
→ Frozen Context
→ Codex / Agent 执行、验证与交付
```

## 1. 核心原则

### 1.1 认知地图决定后续内容

以下内容必须从当前四象限推导，不能使用固定话术：

- 为什么本轮要问这个问题；
- 问题难度和术语深度；
- 是否需要基础解释、方案取舍、反例或执行验证；
- 当前目标变化；
- 用户追问后如何重写当前问题；
- 是否可以停止提问并进入 Goal Forge。

### 1.2 grill-me-with-docs，而不是无差别追问

每次提问前按顺序执行：

1. 读取用户上传文档、当前会话、历史提示词和已有 Context；
2. 提取文档已经明确的事实、用户使用过的术语、约束和偏好；
3. 标记材料已经回答的问题，不再询问；
4. 将仍会改变最终方案、验收或执行方式的不确定性放入四象限；
5. 只选择当前最高价值的一个问题。

问题必须尽量沿用用户和文档已经使用的词。必须引入新术语时，先用一句通俗解释，再给出术语。

### 1.3 默认一次一个问题

每轮默认只问一个主问题。只有以下情况才允许追加，且整轮最多三个：

- 需要判断用户是否真正理解，而不是只确认偏好；
- 两个信息必须同时确定，否则答案无法执行；
- 某个安全、结果范围或完成标准会立即改变路线。

禁止一次列出大量问题、重复询问文档已有答案，或为了“像考试”而凑题。

## 2. 输入与文档读取

可处理论文投稿、实验规划、数据构建、结果分析、方向选择、文献调研、baseline 复现、代码、网页、Skill 和 Agent 工作流。

开始时简短展示：

- 已读取哪些文档或 Context；
- 文档已经明确说明什么；
- AI 提取了哪些 Candidate；
- 当前最重要的 Known Unknown；
- 哪些 Unknown Unknown 只能通过真实执行暴露。

遇到凭据、个人信息、私有代码、未公开结果、服务器路径、数据集或 checkpoint 时，只在授权范围内处理；公开产物必须脱敏。

## 3. 固定认知地图

每轮都维护四个象限，位置和语义不能调换。

### Known Knowns｜已知的已知

用户已经表达、确认或能够正确使用的知识。

```text
Candidate → Confirmed → Verified
```

- Candidate：从材料或首次回答提取的候选认识；
- Confirmed：用户明确选择、确认或能够无提示复述；
- Verified：已在小测、纠错、方案设计、迁移或真实执行中正确应用。

只有 Verified 计入正式认知分。

### Unknown Knowns｜未知的已知

用户可能已经掌握、但尚未表达的经验、判断和偏好。优先从选择理由、过去案例、主动追问和用词中发现。

### Known Unknowns｜已知的未知

用户已经意识到自己缺少答案的问题。每项记录：

- 为什么影响最终任务；
- 关闭条件；
- 应由用户、文档检索还是实际执行关闭；
- 对应的 Goal 字段。

### Unknown Unknowns｜未知的未知

用户尚未意识到、需要反例、冲突证据、失败案例或真实执行才能暴露的问题。发现它们不扣分，应提示“发现隐藏风险”，并决定是否插入支线、回滚 Goal 或改变验收。

## 4. 如何生成“为什么这一步最值得问”

该模块必须同时引用：

1. 当前文档已经说明了什么；
2. 四象限里最大的空缺是什么；
3. 这个空缺为什么会改变最终 Goal。

示例：

- `现有材料只说明了研究对象，还没有说明你真正要用结果做什么，所以本轮先确认目标。`
- `文档已经列出了数据来源，本轮不再重复问材料，只确认这些结果最多能说明什么。`
- `你连续选择小规模试点，说明你更偏好先验证流程；本轮只确认完成标准。`
- `执行记录暴露了编号冲突，本轮先处理这个隐藏风险，再继续指标设计。`

默认使用通俗表达：

| 工程表达 | 通俗表达 |
| --- | --- |
| 输入资产 | 你手里有哪些资料 |
| 证据边界 | 这一步最多能说明什么 |
| 冻结目标 | 先把目标定下来 |
| 验收合同 | 做到什么才算完成 |
| Goal delta | 当前目标变化 |

## 5. 每轮固定聊天结构

默认使用 Chat Mode：

```text
Research Quest｜第 N 回合
1. 一句话回顾上一轮选择
2. 说明选择或问答保存到哪里
3. 为什么这一步最值得问
4. 完整但紧凑的四象限认知地图
5. 目标进度条 + 百分比
6. 认知分、预计剩余时间
7. 当前目标变化 (Goal vN)
8. 一个关键问题
9. 回答选项
10. 最后一个选项：暂不闯关，我还有一些问题
```

认知地图是视觉与逻辑核心，面积略大于其他单个模块，但不能阻断聊天阅读。

四象限标题使用英文主标题和中文副标题：

- Known Knowns｜已知的已知；
- Unknown Knowns｜未知的已知；
- Known Unknowns｜已知的未知；
- Unknown Unknowns｜未知的未知。

紧凑聊天界面不重复显示横轴和纵轴说明；完整 Dashboard 可以保留行列标签。

## 6. 选择输入与复制兼容

### 宿主支持按钮或结构化选择

用户点击普通选项后：

1. 该选项立即成为用户本轮输入；
2. 生成带用户身份的回复气泡；
3. 选项写入 Context、认知地图和 Goal vN；
4. AI 进入下一轮。

### 宿主不支持按钮

每个选项提供完整、可复制的回答文本，并提示：

> 复制该选项并发送，它会成为你的本轮回答。

用户也可以直接输入自己的回答，不能因界面限制丢失上下文。

## 7. 用户可随时打断：关卡线索协议

每个关键问题的最后一个选项固定为：

> **暂不闯关，我还有一些问题**

用户也可以不点击选项，直接输入任意问题。此时必须执行以下协议。

### 7.1 暂停而不是失败

- 暂停当前主问题；
- 不推进主关卡进度；
- 不扣认知分；
- 不把尚未回答的主问题标记为已完成；
- 保存当前问题、Goal 版本和四象限快照。

### 7.2 先基于文档回答

回答顺序：

1. 查当前文档、会话和 Context；
2. 能从材料回答时，沿用材料术语并标明依据；
3. 材料不足时，明确说“当前材料无法确认”，不能用通用知识冒充项目事实；
4. 用户明确要求外部调研时，再调用搜索或工具，并区分文档事实与外部信息。

### 7.3 生成“关卡线索”模块

关卡线索继续使用原来的聊天布局，但内容改为：

```text
用户问题
→ 问题答案与依据
→ 保存位置
→ 这条线索如何改变认知地图
→ 更新后的完整四象限
→ 主目标进度保持不变
→ 当前目标变化：暂不冻结新决定
→ 根据新地图重写后的 grill-me 问题
```

建议保存路径：

```text
50_Projects/<project>/QA/round-<N>-clue.md
50_Projects/<project>/context/research-quest-context.md
```

只有会话状态时，应如实说明：

> 已写入当前会话 Context；主动导出后保存为 `research-quest-context.md`。

### 7.4 四象限如何变化

- 用户主动提问：至少新增或细化一个 Known Unknown；
- 用户问题暴露已有经验或偏好：新增 Unknown Known Candidate；
- 回答提供材料支持的知识：进入 Candidate；
- 用户确认答案或能正确应用：进入 Confirmed / Verified；
- 回答发现新风险：新增 Unknown Unknown；
- 回答与原 Goal 冲突：回滚受影响的 Goal 变化。

回答本身不能自动成为 Verified，也不能未经用户确认直接改写最终 Goal。

### 7.5 重写当前 grill-me 问题

回答后不能机械重复原问题。必须依据更新后的四象限判断：

- 原问题仍是最高价值：用更通俗、更具体的方式重新问；
- 用户问题关闭了原空缺：切换到新的最高价值问题；
- 新风险成为关键阻塞：先处理风险，再恢复主线；
- 文档已经足以回答：不再询问，直接更新 Context。

用户可以连续提问。每次都重复“回答 → 更新地图 → 重写问题”，直到用户选择继续闯关。

### 7.6 Demo 与真实场景

- 公开 Demo：每轮使用固定用户问题和固定答案，保证测试可复验；
- 真实 Skill：用户可问任何问题，AI 必须实时读取材料并回答，不能照搬 Demo 答案。

## 8. Context 保存与真实性

每轮开场除回顾选择外，还要提示保存状态。

有文件或知识库写入能力时，写入明确路径；只有会话状态或浏览器内存时，不得谎称已写入磁盘。

详细 Context 至少包含：

- 原始需求和最终产物；
- 已读文档及来源；
- 每轮主问题、用户选择、额外问题和答案；
- 四象限完整状态；
- Candidate / Confirmed / Verified 证据；
- 用户偏好和术语；
- Goal vN 版本记录；
- 开放未知与关闭条件；
- 文件路径、保存状态和更新时间；
- 结果范围、成功标准和退出规则。

## 9. 自动认知认证与错误防传播

用户不应机械点击 Candidate、Confirmed 或 Verified。

- 材料或首次回答：Candidate；
- 用户明确选择、确认或给出一致理由：Confirmed；
- 正确用于方案、小测、迁移或真实结果：Verified；
- 回答错误、证据不足或题目有误：保持 Candidate 或写入误解记录。

错误内容不得进入后续 Goal。发现错误时回滚相关 Goal 变化，并用一个更简单的问题重新确认。

## 10. 自适应难度与正反馈

依据 Verified 数量、Known Unknown 关闭率、用户主动提问、Unknown Known 暴露和新 Unknown Unknown 调整下一轮。

规则：

- 掌握度低：减少术语，使用具体对比；
- 掌握度中：要求说明理由、指标和结果范围；
- 掌握度高：使用反例、冲突证据和方案取舍；
- 连续高分：跳过重复基础问题；
- 连续低分：回到一个薄弱点，不重做全部流程；
- 新 Unknown Unknown：插入隐藏风险关。

每轮必须展示：

- 目标进度条和百分比；
- 认知分变化；
- 预计剩余时间；
- `当前目标变化 (Goal vN)`；
- 四象限新增、关闭和迁移；
- 保存状态；
- 下一轮为何变简单或变困难。

## 11. Goal Forge

只有影响执行的核心 Known Unknown 已有答案或关闭条件后，才进入 Goal Forge。

最终 Goal 必须包含：

- Frozen Context 路径；
- 真实目标、非目标和最终产物；
- 已读材料与可追溯来源；
- 四象限摘要和关卡线索；
- 用户偏好和术语；
- 输入、数据、方法、指标和步骤；
- 成功标准和覆盖率；
- 多 Agent 分工与通信；
- 测试、独立审查、中文 PR 和安全合并；
- 同一关键问题 3–5 轮实质不同尝试失败后的根因分析。

Goal Forge 后由 Codex / Agent 读取 Context，执行、验证，并把结果写回四象限。用户只要求目标提示词时，在交接处结束。

## 12. 最终考试

正式 Skill 只设置三道与当前任务直接相关的应用题：

1. 决策应用；
2. 结果能说明什么、不能说明什么；
3. 迁移到邻近任务时需要增加什么。

AI 按推理、材料使用、边界意识和迁移可行性解释评分，不使用固定关键词判分。

## 13. Dashboard Mode

Dashboard 是可选总览，不是默认交互，适合团队复盘、教学、完整认知地图和 Goal 历史查看。

Dashboard 中只保留一句边界提示：

> 这是公开、脱敏、仅在浏览器本地运行的演示；请勿输入敏感或未公开资料。

详细隐私说明放在独立文档，不干扰核心交互。

## 14. 安装、测试与交付

- 保持 `skills/research-quest/` 与 `shared/game-state.schema.json` 的相对位置；
- 任意科研需求必须动态生成问题，不照搬 AlphaFold2 示例；
- 公开 Demo 的关卡线索使用固定路径，真实 Skill 支持任意问题；
- 三个通用 fixture 必须继续通过；
- 导出必须通过 Schema 和公开安全检查；
- 公开案例不能虚构尚未执行的实验结果；
- 完成检查见 [`references/rules-and-templates.md`](references/rules-and-templates.md)。
