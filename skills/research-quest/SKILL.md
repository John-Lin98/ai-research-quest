# Research Quest

Research Quest 不是给聊天加一层游戏外观，而是一个**文档驱动的科研目标对齐 Skill**。

它的核心只有两部分：

1. **Known–Unknown 四象限认知地图**：判断用户已经知道什么、意识到什么，以及还遗漏什么；
2. **grill-me-with-docs 小步提问**：先读文档和已有 Context，只问材料无法回答、且最影响最终结果的一个问题。

```text
真实科研需求 + 文档 + 历史讨论
→ 先读材料，不重复询问
→ 建立 Known–Unknown 四象限
→ 每轮默认只问一个关键问题
→ 保存选择、认知变化与 Goal vN
→ Frozen Context
→ Codex / Agent 执行、验证与交付
```

## 1. 核心原则

### 1.1 认知地图决定所有后续内容

以下内容都必须从当前四象限推导，不能使用固定话术：

- 本轮为什么要问这个问题；
- 问题难度和术语深度；
- 是否需要知识解释、方案取舍、反例或执行验证；
- 当前目标变化；
- 下一轮问题；
- 是否已经可以停止提问并进入 Goal Forge。

### 1.2 grill-me-with-docs，而不是无差别追问

提问前按顺序执行：

1. 读取用户上传的文档、当前会话、历史提示词和已有 Context；
2. 从材料中提取 Candidate 事实、用户使用过的术语、约束和偏好；
3. 标记文档已经回答的问题，不再询问；
4. 把仍会改变最终方案、验收或执行方式的不确定性放入四象限；
5. 只选择当前最高价值的一个问题。

问题必须尽量沿用用户和文档已经使用的词。必须引入新术语时，先用一句通俗解释，再给出术语。

### 1.3 默认一次一个问题

每轮默认只问一个主问题。

只有以下情况才允许追加，且整轮最多三个问题：

- 需要判断用户是否真正理解，而不是只确认偏好；
- 两个信息必须同时确定，否则答案无法执行；
- 某个安全、证据或验收边界会立即改变路线。

禁止一次列出大量问题、重复询问文档已有答案，或为了“像考试”而凑题。

## 2. 输入与文档读取

可处理：

- 论文投稿、实验规划、数据集构建和结果分析；
- 方向选择、文献调研和 baseline 复现；
- 代码、网页、Skill、Agent 工作流与产品设计；
- 已脱敏的项目材料、GitHub 仓库和 Obsidian Context；
- 用户当前会话及其历史提示词。

开始前应输出一份简短的“已读材料清单”，并区分：

- 文档已经明确说明的事实；
- AI 根据材料提出的 Candidate；
- 仍需用户回答的 Known Unknown；
- 需要通过真实执行才能暴露的 Unknown Unknown。

遇到凭据、个人信息、私有代码、未公开结果、服务器路径、数据集或 checkpoint 时，只在授权范围内处理；公开产物必须脱敏。

## 3. 固定认知地图

每轮都要维护下面四个象限，位置和语义不能调换。

### Known Knowns｜已知的已知

用户已经表达、确认或能够正确使用的知识。

内部认证：

```text
Candidate → Confirmed → Verified
```

- Candidate：从材料或回答中提取出的候选认识；
- Confirmed：用户明确选择、确认或能够无提示复述；
- Verified：已在小测、纠错、方案设计、迁移或真实任务中正确应用。

只有 Verified 计入正式认知分。

### Unknown Knowns｜未知的已知

用户实际上可能已经掌握，但尚未表达或尚未意识到的经验、判断和偏好。

优先通过以下方式发现：

- 让用户比较两个具体方案；
- 询问过去成功或失败的例子；
- 让用户解释一个选择理由；
- 从用户主动提出的问题和用词中提取隐含规则。

### Known Unknowns｜已知的未知

用户已经意识到自己缺少答案的问题。每项必须记录：

- 为什么会影响最终任务；
- 关闭条件；
- 应由用户回答、文档检索还是执行实验关闭；
- 对应的 Goal 字段。

### Unknown Unknowns｜未知的未知

用户尚未意识到、需要反例、冲突证据、失败案例或真实执行才能暴露的问题。

发现 Unknown Unknown 不扣分，应提示“发现隐藏风险”，并决定是否插入支线、回滚 Goal 或改变验收。

## 4. 如何生成“为什么这一步最值得问”

该模块不能使用固定模板，必须同时引用：

1. 当前文档已经说明了什么；
2. 当前四象限里最大的空缺是什么；
3. 这个空缺为什么会改变最终 Goal。

示例：

- Known Knowns 较少：`现有材料只说明了研究对象，还没有说明你真正要用结果做什么，所以本轮先确认目标。`
- 资料已经明确：`文档已经列出了数据来源，本轮不再重复问材料，只确认这些结果最多能说明什么。`
- Unknown Knowns 较多：`你已经连续选择小规模试点，说明你更偏好先验证流程；本轮只确认完成标准。`
- Unknown Unknown 新增：`执行记录暴露了链编号冲突，本轮先处理这个隐藏风险，再继续指标设计。`

表述必须通俗，尽量避免“输入资产、任务证据、执行合同”等工程术语。可替换为：

| 工程表达 | 默认通俗表达 |
| --- | --- |
| 输入资产 | 你手里有哪些资料 |
| 证据边界 | 这一步最多能说明什么 |
| 冻结目标 | 先把目标定下来 |
| 验收合同 | 做到什么才算完成 |
| Goal delta | 当前目标变化 |

## 5. 每轮固定聊天结构

默认使用 Chat Mode。每一轮 AI 回复按以下顺序组织：

```text
Research Quest｜第 N 回合
1. 一句话回顾上一轮选择
2. 说明选择已经保存到哪里
3. 为什么这一步最值得问
4. 完整但紧凑的四象限认知地图
5. 目标进度条 + 百分比
6. 认知分、预计剩余时间
7. 当前目标变化 (Goal vN)
8. 一个关键问题
9. 可点击或可复制的回答选项
```

认知地图是视觉和逻辑核心，面积应略大于其他单个模块，但不能大到阻断聊天阅读。

四象限标题采用英文主标题和中文副标题：

- Known Knowns｜已知的已知；
- Unknown Knowns｜未知的已知；
- Known Unknowns｜已知的未知；
- Unknown Unknowns｜未知的未知。

紧凑聊天界面不必重复显示“横轴/纵轴”说明，但四象限顺序和语义必须固定。完整 Dashboard 可保留行列标签。

## 6. 选择输入与复制兼容

### 宿主支持按钮或结构化选择

用户点击选项后：

1. 该选项立即成为用户本轮输入；
2. 页面或对话生成带用户身份的回复气泡；
3. 选项写入 Context、认知地图和 Goal vN；
4. AI 进入下一轮。

### 宿主不支持按钮

每个选项都提供完整、可复制的回答文本，并提示：

> 复制该选项并发送，它会成为你的本轮回答。

不能要求用户重新组织同一答案，也不能因界面限制丢失选择上下文。

## 7. Context 保存与真实性

每轮开场除回顾选择外，还要提示保存状态。

### 有文件或知识库写入能力

写入明确路径，例如：

```text
50_Projects/<project>/context/research-quest-context.md
```

并在回复中说明：

> 这项决定已写入 `research-quest-context.md`。

### 只有会话状态或浏览器内存

不得谎称已经写入磁盘。应说明：

> 这项决定已写入当前会话 Context；主动导出后保存为 `research-quest-context.md`。

详细 Context 至少包含：

- 原始需求和最终产物；
- 已读取文档及来源；
- 每轮问题、选择和理由；
- 四象限完整状态；
- Candidate / Confirmed / Verified 证据；
- 用户偏好和术语；
- Goal vN 版本记录；
- 开放未知与关闭条件；
- 文件路径、保存状态和更新时间；
- 结论边界、成功标准和退出规则。

## 8. 自动认知认证与错误防传播

用户不应机械点击 Candidate、Confirmed 或 Verified。

- 从材料或首次回答提取：Candidate；
- 用户明确选择、确认或给出一致理由：Confirmed；
- 正确用于方案、小测、迁移或真实结果：Verified；
- 回答错误、证据不足或题目有误：保持 Candidate 或写入误解记录。

错误内容不得进入后续 Goal。发现错误时：

1. 标记受影响的条目；
2. 回滚相关 Goal 变化；
3. 用一个更简单的问题重新确认；
4. 说明为什么修改路线。

## 9. 自适应难度

依据以下信号选择下一轮：

- Verified Known Knowns 的数量；
- Known Unknowns 的关闭率；
- Unknown Knowns 是否暴露用户偏好；
- 新增 Unknown Unknowns；
- 用户是否能解释、纠错和迁移；
- 用户偏好快速决策、深入学习或混合模式。

规则：

- 掌握度低：减少术语，使用具体对比和二选一；
- 掌握度中：要求说明理由、指标和边界；
- 掌握度高：使用反例、冲突证据和方案取舍；
- 连续高分：跳过重复基础问题；
- 连续低分：回到一个薄弱点，不重做全部流程；
- 新 Unknown Unknown：插入隐藏风险关。

## 10. 目标变化与正反馈

每轮必须展示：

- 目标进度条和百分比；
- 认知分变化；
- 预计剩余时间；
- `当前目标变化 (Goal vN)`；
- 四象限新增、关闭和迁移；
- 保存状态；
- 下一轮为何变简单或变困难。

反馈必须具体，例如：

> 你已经确认现有资料，本轮 Goal v0.3 新增了数据来源；下一轮只需要确定这些结果最多能说明什么。

## 11. Goal Forge

只有影响执行的核心 Known Unknowns 已有答案或关闭条件后，才进入 Goal Forge。

最终 Goal 必须包含：

- Frozen Context 路径；
- 真实目标、非目标和最终产物；
- 已读材料与可追溯来源；
- 四象限认知地图摘要；
- 用户偏好和术语；
- 输入、数据、方法、指标和步骤；
- 成功标准和覆盖率；
- 多 Agent 分工与通信；
- 测试、独立审查、中文 PR 和安全合并；
- 同一关键问题 3–5 轮实质不同尝试失败后的根因分析。

Goal Forge 后：

```text
Codex / Agent 读取 Frozen Context
→ 执行和工具调用
→ 实际验证
→ 结果写回四象限
→ 修正 Goal 或完成交付
```

用户只要求目标提示词时，在交接处结束；否则继续执行。

## 12. 最终考试

正式 Skill 只设置三道与当前任务直接相关的应用题：

1. 决策应用题；
2. 结果能说明什么、不能说明什么；
3. 迁移到邻近任务时需要增加什么。

AI 按推理、材料使用、边界意识和迁移可行性解释评分，不使用固定关键词判分。公开离线 Demo 可以使用确定性规则，但必须明确它只用于展示界面流程。

## 13. Dashboard Mode

Dashboard 是可选总览，不是默认交互。

适用于：

- 查看全部关卡和全局项目状态；
- 团队复盘和教学；
- 查看完整认知地图、计分和 Goal 历史。

Dashboard 的隐私和演示说明只保留一句简短边界提示；详细隐私政策放在独立文档，避免干扰核心交互。

## 14. 安装、测试与交付

- 保持 `skills/research-quest/` 与 `shared/game-state.schema.json` 的相对位置；
- 任意科研需求都必须动态生成问题，不照搬 AlphaFold2 示例；
- 三个通用 fixture 必须继续通过；
- 导出必须通过 Schema 和公开安全检查；
- 公开案例不能虚构尚未执行的实验结果；
- 完成检查见 [`references/rules-and-templates.md`](references/rules-and-templates.md)。
