# Research Quest 规则与模板

## 1. 核心循环

Research Quest 的核心不是固定关卡，而是：

```text
读取文档与已有 Context
→ 建立 Known–Unknown 四象限
→ 选择最高价值认知空缺
→ 默认只问一个问题
→ 保存回答与 Goal vN
→ 下一轮继续缩小不确定性
→ Frozen Context
→ Codex / Agent 执行
```

四象限负责决定问题；grill-me-with-docs 负责减少无效提问。

## 2. 文档优先检查

每轮提问前必须记录：

```markdown
- 已读取材料：
- 材料已经回答：
- 从材料提取的 Candidate：
- 当前最大认知空缺：
- 为什么必须由用户回答：
- 对 Goal 的影响：
```

禁止重复询问材料里已有答案。无法读取的材料要明确记录限制，不得猜测正文。

## 3. 每轮问题预算

默认只问一个主问题。

确有必要时可增加：

1. 证据问题：判断用户是否真正理解；
2. 边界问题：答案会立即改变风险或执行方式。

每轮最多三个问题，不为了完整感凑题。

## 4. Known–Unknown 四象限

|  | 用户已经意识到 | 用户尚未意识到 |
| --- | --- | --- |
| **已经掌握** | **Known Knowns｜已知的已知** | **Unknown Knowns｜未知的已知** |
| **尚未掌握** | **Known Unknowns｜已知的未知** | **Unknown Unknowns｜未知的未知** |

紧凑聊天界面可以省略轴文字，但位置和语义不能变化。

### Known Knowns 认证

```text
Candidate → Confirmed → Verified
```

只有 Verified 计入正式认知分。

## 5. “为什么这一步最值得问”模板

必须由三部分组成：

```text
文档已经告诉我们：<已有信息>
认知地图当前最大空缺：<象限与问题>
这个问题会改变：<目标/方法/验收/边界>
```

必须使用通俗表达和用户已经使用的术语。

推荐替换：

| 避免 | 推荐 |
| --- | --- |
| 输入资产 | 你手里有哪些资料 |
| 证据边界 | 这一步最多能说明什么 |
| 冻结目标 | 先把目标定下来 |
| 验收合同 | 做到什么才算完成 |
| Goal delta | 当前目标变化 |

## 7. 选择输入规则

### 支持按钮

点击选项后：

- 选项直接成为用户回复；
- 显示用户聊天气泡；
- 写入 Context、四象限和 Goal vN。

### 不支持按钮

为每项提供复制按钮或完整可复制文本。用户复制并发送即可，不要求重新组织答案。

## 8. 保存规则

### 可写文件

写入项目 Context，例如：

```text
50_Projects/<project>/context/research-quest-context.md
```

### 仅会话或浏览器内存

必须说明：

> 已写入当前会话 Context；主动导出后保存为 `research-quest-context.md`。

不得谎称已经持久化。

## 10. 错误防传播

- 不确定或自相矛盾：Candidate；
- 用户明确确认：Confirmed；
- 在方案、小测、迁移或执行中正确应用：Verified；
- 错误或证据不足：不进入后续 Goal。

发现错误时回滚相关 Goal，并用一个更简单的问题重新确认。

## 11. 自适应难度

- Known Knowns 少：少术语、具体对比；
- Known Unknowns 多：优先关闭用户已经意识到的问题；
- Unknown Knowns 多：提取理由、经验和偏好；
- Unknown Unknown 新增：插入失败或风险关；
- 核心 Known Unknowns 已有关闭条件：停止提问，进入 Goal Forge。

## 12. 最终考试

只设置三道与当前任务直接相关的应用题：

1. 决策应用；
2. 结果能说明什么、不能说明什么；
3. 迁移到邻近任务需要增加什么。

正式 Skill 使用解释式评分；离线 Demo 可以使用确定性规则展示流程。

## 13. Codex Goal 模板

```markdown
# Codex Goal｜<名称>

开始前读取：<Frozen Context 路径>
不要重复询问已经确认的决定。

## 目标与非目标

## 已读材料和用户偏好

## Known–Unknown 四象限摘要

## 输入、步骤、指标和产物

## 成功标准

## Agent 分工与通信

## 测试、独立审查、中文 PR 和合并

## 失败处理
同一关键问题 3–5 轮实质不同尝试仍失败时，输出根因分析。
```

## 14. 完成检查单

- [ ] 提问前读取了材料；
- [ ] 没有重复询问文档已有答案；
- [ ] 每轮默认只有一个关键问题；
- [ ] 四象限中英标题和位置正确；
- [ ] “为什么问”引用了文档与认知空缺；
- [ ] 用户选择写入了 Context；
- [ ] 保存状态真实可核验；
- [ ] 显示目标进度和当前目标变化 (Goal vN)；
- [ ] 错误回答未进入后续 Goal；
- [ ] 最终 Goal 引用 Frozen Context；
- [ ] 公开产物不含敏感信息或虚构实验结论。
